GNN-BERT Music Context Understanding
==================================

This project is a machine learning project for music context understanding using:
- graph neural networks (GNN)
- BERT text encoder
- multi-task classification and regression
- MusicCaps, GTZAN, and DEAM datasets

It is built for research / demo use, not for a Web app or package install.

IMPORTANT: This project is large. The zip may contain many GB of data and trained model files.
If you unzip it to a normal Windows folder, it should still work as long as you have enough disk space.

Recommended folder path:
- Short path is best on Windows. Example: C:\gnn-music or C:\work\gnn-music
- Avoid very long paths like C:\Users\YourName\OneDrive\...\project\...

------------------------------------------------------------
1) WHAT IS IN THIS ZIP
------------------------------------------------------------

Project root folders and files:

config.yaml
  Main project configuration file. Contains all hyperparameters, dataset paths, model settings,
  training settings, and seed values. Almost every script reads this file.

README.md
  High-level overview, setup instructions, and run commands.

requirements.txt
  Core Python dependencies.

requirements.lock.txt
  Exact pinned dependency set used for the reported environment.

src/
  Main Python source code.
  Files include:
  - audio_features.py: mel, chroma, MFCC, audio feature extraction
  - graph_builder.py: builds segment graph and chord graph structures
  - graph_dataset.py: dataset loading and batching helpers
  - gnn_model.py: graph models such as GraphSAGE / GAT
  - bert_encoder.py: BERT/DistilBERT text model wrappers
  - fusion_model.py: audio + text fusion models
  - contrastive.py: contrastive audio-text training and retrieval code
  - trainer.py: training loop shared across tasks
  - metrics.py: evaluation metrics
  - data_loading.py: dataset loaders for GTZAN, MusicCaps, and DEAM
  - utils.py: helper utilities
  - __init__.py: package marker

scripts/
  Driver scripts to run data download, preprocessing, training, evaluation, prediction.
  Files include:
  - download_data.py: downloads raw datasets metadata and archives
  - download_musiccaps_audio.py: fetches MusicCaps audio via YouTube IDs
  - preprocess.py: builds features and graphs from raw audio
  - train.py: trains the models for the project tasks
  - evaluate.py: generates plots/tables/metrics summaries
  - calibrate_tau.py: tunes similarity threshold for graph edges
  - corpus_stats.py: dataset-level summary statistics
  - predict.py: predict genre/tags/emotion for a new custom audio file

notebooks/
  Analysis and demo notebooks.
  - eda.ipynb: exploratory data analysis and dataset understanding
  - demo_context.ipynb: trained-model demonstrations of what the models learned

report/
  Project report files.
  - report.tex: LaTeX source
  - report.md: rendered markdown version (good for GitHub)
  - numbers.tex: generated numbers from metrics
  - README.md: report build guide

results/
  Outputs and trained artifacts.
  - metrics.json: saved evaluation metrics for all runs
  - plots/: charts and figures
  - tables/: summary tables
  - checkpoints/: saved trained model weights (.pt files)
  - graph_samples/: sample graphs exported as JSON / .pt
  - preds/: prediction outputs
  - retrieval_examples/: retrieval examples
  - corpus_stats.json: data statistics
  - tau_calibration.json: calibration data for similarity threshold

data/
  Raw and processed datasets. This is usually the largest part of the project.
  - raw/: source datasets and downloaded archive files
  - processed/: precomputed feature tensors and graph caches
  - splits/: train/val/test split metadata

tools/
  Project utility scripts for generating report and notebooks.

------------------------------------------------------------
2) WHAT THE IMPORTANT PATHS DO
------------------------------------------------------------

data/raw/
  Downloaded raw corpora and audio archives.
  This is where you find:
  - GTZAN genre audio
  - DEAM audio and annotations
  - MusicCaps metadata and audio
  - raw archives such as .zip / .tar.gz files
  This directory is usually very large and may be excluded from public Git repositories.

data/processed/
  Processed numpy / torch data produced by preprocessing.
  These are cached graphs and feature caches used to train and evaluate quickly.
  This avoids re-building graphs from scratch every time.

data/splits/
  Train/validation/test split information for the datasets.

results/checkpoints/
  Trained model files. These are the saved weights for each task.
  Example files:
  - task1_bert_masked.pt
  - task2_gnn_sage_segment.pt
  - task3_cross_attention.pt
  - task4_contrastive.pt

results/metrics.json
  Main summary of evaluation results, losses, and metrics.
  The report pulls numbers from this file.

results/plots/
  Generated plots comparing models, tasks, and failure cases.

results/tables/
  Evaluation tables saved after running evaluate.py.

src/
  All actual code implementing the project.

scripts/
  The exact scripts you use to do the project workflow.

notebooks/demo_context.ipynb
  Best notebook to run if you want to see trained model behavior on real data.

4) SETUP ON WINDOWS
------------------------------------------------------------

Open a terminal (PowerShell or Command Prompt) in the project folder.

1. Move into the project directory:
   cd "C:\path\to\gnn-bert-music-context"

2. Create a short-path virtual environment.
   It is strongly recommended to use a short path such as C:\v or C:\tmp\venv because long Windows paths can cause installer issues.

   Example:
   py -m venv C:\v\gnn-bert
   C:\v\gnn-bert\Scripts\Activate.ps1

   If using Command Prompt instead:
   C:\v\gnn-bert\Scripts\activate.bat

3. Install PyTorch CPU version first:
   pip install torch --index-url https://download.pytorch.org/whl/cpu

4. Install the rest of the dependencies:
   pip install -r requirements.txt

5. Confirm it works:
   python --version
   python -c "import torch, transformers, sklearn, librosa; print('ok')"

------------------------------------------------------------
6) HOW TO RUN THE FULL PROJECT
------------------------------------------------------------

The normal project flow is this:

1. Download the raw data:
   python scripts/download_data.py

2. Download MusicCaps audio (this step may take a while and can be rate-limited by YouTube):
   python scripts/download_musiccaps_audio.py --workers 6

3. Preprocess audio into feature tensors and graph objects:
   python scripts/preprocess.py --dataset all --save-mel --export-json 24

4. Train the model(s):
   python scripts/train.py --task all

   You can also run one task only:
   python scripts/train.py --task 1
   python scripts/train.py --task 2
   python scripts/train.py --task 3
   python scripts/train.py --task 4

   There is also a quick smoke test mode:
   python scripts/train.py --task all --quick

5. Evaluate the results:
   python scripts/evaluate.py

6. Compute corpus statistics:
   python scripts/corpus_stats.py

7. Regenerate report / numbers if needed:
   Follow the instructions in report/README.md

------------------------------------------------------------
7) HOW TO RUN A PREDICTION ON YOUR OWN AUDIO
------------------------------------------------------------

This project includes a custom prediction script.

Example:
   python scripts/predict.py my_song.mp3

With a caption for cross-attention fusion:
   python scripts/predict.py my_song.mp3 --caption "a mellow jazz trio with brushed drums"

Machine-readable JSON output:
   python scripts/predict.py my_song.mp3 --caption "a mellow jazz trio with brushed drums" --json out.json

Notes:
- It expects a file that librosa can read.
- It only uses the first 30 seconds of audio, matching the project training setup.
- Genre is limited to GTZAN classes.
- Tags are limited to the 50 MusicCaps aspect tags used by the model.

How to run:

------------------------------------------------------------
9) WHAT EACH TASK DOES
------------------------------------------------------------

Task 1: caption -> tag prediction
- Uses MusicCaps captions and tag labels.
- A DistilBERT model predicts tags from text.
- Important: the README explains that surface-form matching from captions can leak labels.
- This is one of the main project findings.

Task 2: genre classification with graphs
- Uses GTZAN graphs built from segment-level features.
- Graph neural network predicts genre.
- Includes ablations and baselines.

Task 3: audio + text fusion
- Uses graphs + captions together.
- Predicts tags and emotion (valence / arousal).
- Includes fusion modes such as cross_attention, concat, gnn_only, bert_only.

Task 4: contrastive learning / retrieval
- Learns shared embedding space between audio graphs and text captions.
- Allows free-text retrieval and zero-shot tagging.

10) IMPORTANT PROJECT NOTES FOR NEW USERS
------------------------------------------------------------

- This project is CPU-based and was run without GPU.
- The configuration is controlled in config.yaml.
- Data is large. The project may not fit in a tiny drive.
- The code is in src/, while the pipeline scripts are in scripts/.
- Checkpoint files (.pt) may be large; they are not small text model files.
- Some steps can take a long time, especially:
  - MusicCaps audio recovery
  - preprocessing
  - training
- If the zip lacks data/raw or results/checkpoints, you must run the pipeline or restore those directories before running the notebook.
- The project expects paths relative to the root folder.

------------------------------------------------------------
12) TROUBLESHOOTING
------------------------------------------------------------

Issue: pip fails with long path / WinError 206
- Use a short path such as C:\v or C:\tmp\venv

Issue: Import errors like No module named torch
- Activate the venv and install requirements again

Issue: Notebook cannot find src modules
- Make sure the project root is the working directory
- The notebook often adds the project root to sys.path automatically

Issue: Missing data or checkpoint files
- Run the preprocessing and/or training scripts
- Check that data/raw and results/checkpoints exist

Issue: Large runtime or slow training
- This is expected on CPU; the project is designed for CPU-only use and can take hours on slower machines

------------------------------------------------------------
13) GOOD RULES FOR SHARING OR REUSING THIS PROJECT
------------------------------------------------------------

- Do not upload generated virtual environments (.venv)
- Do not upload huge downloaded datasets if you do not need to share them
- Keep the source code, config, scripts, notebooks, and report files
- Keep results/metrics.json and small output files if useful
- For public GitHub, it is usually better to keep only code and small metadata, and store large data/checkpoints elsewhere

If someone gets the zip and wants to run the project:
